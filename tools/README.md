# أدوات المطوّر

كل الأدوات تُشغَّل من جذر المستودع بـ `node` (الإصدار 22)، ولا تحتاج تثبيت حزم إلا اختبارات `tests/` (`cd tests && npm install`).
لا تعدّل أي أداة قاعدة البيانات الحية، وكلها تطبع سطر خلاصة في آخرها وتخرج بالرمز 1 عند الفشل.

## أي أداة لأي عمل

| أريد أن… | الأمر | الوقت |
|---|---|---|
| أتأكد أن المستودع سليم قبل أي شيء | `node tools/doctor.mjs` | ثانية |
| أفحص ملفات تحضير (أو zip) قبل رفعها | `node tools/prep-check.mjs <ملف أو مجلد أو zip>` | ثوانٍ |
| أفهم ما حدث لمعلم (تكرار، حصص لم تُحفظ، تواريخ) | `node tools/fill-log.mjs log.json` | ثانية |
| أضيف شجرات نور جديدة إلى الاختبارات | `node tools/noor-tree.mjs export.json --write` | ثانية |
| أعرف أين وصلت كل نسخة (المتجر، الموقع، min_ext_version) | `node tools/versions.mjs` (يحتاج إنترنت) | ثوانٍ |
| أرفع رقم الإصدار | `node tools/bump.mjs` | ثانية |
| أشغّل اختبارات الإصدار وأبني الـ zip | `node tools/suite.mjs --tier full --version X` | ساعات |
| أرى خريطة المشروع | `python3 tools/graphify.py -o /tmp/map.html` | ثوانٍ |

## الأدوات

### `doctor.mjs` — فحص سريع
صياغة كل ملف JavaScript، و`extension/manifest.json` (الإصدار، كل ملف يشير إليه موجود، `key`، رابط الموقع)، والملفات التي تحمّلها صفحات HTML،
وتطابق إعدادات Supabase بين `site/config.js` و`extension/afaq-config.js`، و**أن كل دالة RPC وجدول يناديهما الموقع أو الإضافة معرّفان في
`site/supabase/*.sql`**، وصحة ملفات JSON (أنشطة الدروس وشجرات نور). يعمل تلقائيًا على كل طلب دمج (سير العمل «فحص سريع»).

### `prep-check.mjs` — فحص ملفات التحضير
بلا وسائط يفحص كل الباقات في `/mnt/project-files/afaq-platform/preps/g*/`. يقبل ملفات JSON ومجلدات وملفات zip معًا، و`--only en-9,ar-5`، و`-v` لكل تحذير.
أخطاء: حقول ناقصة، معرّف حصة مكرر، تاريخ ليس صالحًا أو يوم جمعة/سبت، `publishDate` يخالف `pubDate`، زمن الحصة لا يطابق الفترة (40/35)،
حقل أساسي فارغ، **رابط نشاط `play.html?d=…` بلا ملف في `site/games`**. تحذيرات: تواريخ غير متصاعدة، مستوى غير معروف، اسم ملف لا يطابق المعرّف، رابط مكسور.

### `fill-log.mjs` — تحليل «سجل التعبئة»
في لوحة الإدارة ← الطلبات ← «سجل التعبئة» ← **«نسخ للتحليل»**، ثم الصق السجل في ملف أو مباشرة: `pbpaste | node tools/fill-log.mjs -`.
يلخّص كل تشغيلة (النسخة، المادة، النوع، المحفوظ وغير المؤكد والفاشل والمتخطّى) ويكشف: حصة حُفظت مرتين (في تشغيلة أو تشغيلتين)، تشغيلة لم تنته،
نشر يوم جمعة/سبت، حصة قبل سابقتها في الملف، حفظ بلا درس نور، الحصص المزحزحة. `--run <id>` لتشغيلة واحدة بكل أسطرها، `-v` لكل الأسطر.

### `noor-tree.mjs` — شجرات نور الحقيقية للاختبارات
في لوحة الإدارة ← «شجرات نور» ← **«نسخ كل الشجرات للاختبارات»**، ثم `node tools/noor-tree.mjs export.json` يعرض الجديد والمتغيّر،
و`--write` يكتبه في `tests/noor-mock/real-trees/trees.json` (الأكثر رؤية لكل مادة، الفصل الأول)، و`--alias` يجعل الفترة الأخرى تستعمل الشجرة نفسها.
يطبع بعدها أمرَي الاختبار: `align.mjs` (دون متصفح) و`matrix.mjs` على المواد الجديدة. **قاعدة المالك: «حاضر» تُختبر على كل شجرة حقيقية قبل كل إصدار.**

### `versions.mjs` — حالة النسخ
نسخة المستودع، والموقع المنشور (`hader-version.json`)، ومتجر كروم، و`min_ext_version` من الإعدادات، ثم ما يجب فعله
(المتجر متأخر، النشر لم يكتمل، `min_ext_version` أعلى من المتجر = لا أحد يعبّئ!). يحتاج إنترنت: شغّله على حاسوبك أو من GitHub ← Actions ← «حالة نسخ حاضر» ← Run workflow.

### `bump.mjs` — رفع الإصدار
`node tools/bump.mjs` يرفع الرقم الأخير (4.10.18 → 4.10.19)، أو `node tools/bump.mjs 4.11.0`. يرفض رقمًا ليس أعلى (المتجر يرفضه).

### `suite.mjs` — اختبارات الإصدار وسطر الخلاصة
يشغّل الخطوات واحدة بعد أخرى ويحفظ سجل كل منها، ثم يطبع سطر الخلاصة الذي يُرسل مع الـ zip:
```
SUITE PASSED — align 35/35, rich 0, matrix 240/240 (11051), oneper 240/240, real 35/35 (1447), scenarios 19/19, gate 14/14
```
- `--tier full`: لكل تعديل في منطق التعبئة أو التواريخ أو المطابقة أو الحفظ (doctor, align, rich, matrix, oneper, real, scenarios).
- `--tier short`: لتعديل النصوص أو الشاشات أو مسار المعالج فقط (doctor, align, scenarios, matrix عينة 24).
- `--version X`: يضيف خطوة `gate` (`tests/build-release.sh X`: يبني الـ zipين ويجرّبهما) — تُشغَّل فقط إن نجح كل ما قبلها.
- `--steps a,b`: خطوات بعينها. `--logs dir`: مكان السجلات. `-v`: يعرض المخرجات أثناء التشغيل.

لا تشغّل اختبارين بالمتصفح معًا (المعالج 4 أنوية: `--jobs 3` حدّ أعلى). لإيقاف اختبار عالق: `pgrep -f "^node tests/noor"` ثم `kill`.

## إضافة مادة أو صف جديد
1. حوّل ملف المصدر: `node tools/hader-plans-html.mjs "<ملف>.html" preps/<مجلد>/<id>-t1.json --id=<id>` (`<id>` = رمز المادة-الصف، و`-2` للفترتين).
2. افحصه: `node tools/prep-check.mjs preps/<مجلد>/<id>-t1.json -v`.
3. جرّبه على نور المحاكى: `node tests/noor-mock/matrix.mjs --only <id>-t1 --jobs 1`.
4. أنشطة الدروس: `tools/games/plan.mjs` ثم `tools/games/check.mjs site/games/<id>`.
5. اضغط الملفات في zip وارفعها من لوحة الإدارة ← «الباقات» ← «رفع تحاضير كثيرة دفعة واحدة».
6. حين يفتحها أول معلم في نور تصل شجرتها إلى «شجرات نور»: أضفها بـ `noor-tree.mjs` واختبرها.

## إضافة دالة RPC جديدة
اكتبها في ملف `site/supabase/hader-<الموضوع>.sql` (مع `grant execute` واختبارها في تعليق `RESULT OK` كما في الملفات الأخرى)، ثم ناديها من
`extension/remote.js` أو `site/assets/*.js`. `doctor.mjs` يفشل إن نوديت دالة لا تعريف لها في SQL، فيُكتشف نسيان ملف SQL قبل الدمج.
